# Observation, action and data contracts

Task `select_place_v1_permuted_colors_jittered_objects_trays`: two colored rigid cubes (red/green), two physical colored trays (blue/yellow), gray distractor. Object and tray color-to-location assignments are independently permuted per scene, positions jittered. One instruction explicitly chooses both object and destination; four combinations. All scene decisions use the scene seed; model construction has a fixed recorded seed. Scene families remain narrow; no claims about arbitrary natural language or unseen object classes.

MuJoCo world: meters, seconds, z up, fixed tabletop z=0.8. Panda base frame from `robot0_base` body pose. Robot state: joint q (rad), dq (rad/s), world eef xyz (m), world eef quaternion xyzw, finger joint positions (m), total 23 scalars. Camera points are XYZRGB in Panda base frame. These frame conventions are explicit; eef state and point XYZ use different named frames with a fixed recorded transform.

Camera RGB arrays are flipped from robosuite OpenGL bottom-up to top-down. Raw nonlinear depth is converted to metric optical-axis z using MuJoCo near/far and stored float32 losslessly. Intrinsics correspond to top-down images; `get_camera_extrinsic_matrix` includes OpenGL -> OpenCV axis conversion. Store base-from-camera and world-from-base every frame, including the moving wrist. Both cameras and proprio/action sample the same simulation instant before action, timestamp in simulation seconds, 20 Hz. Final observation is stored separately. No segmentation rendered or used by policies.

Workspace crop is a fixed world box x=(-.25,.25), y=(-.31,.31), z=(.79,1.15); invalid/nonpositive depth excluded. 4 mm deterministic voxel first representative, deterministic uniform index subsampling to 512 XYZRGB points with validity mask. Fusion pools calibrated views then applies the same 512-point budget. This differs from original DP3 FPS; report this adaptation. No target-dependent crop. ACT receives both RGB views downsampled from 128 to 64 pixels, robot state, and the same instruction tokens; it has no depth.

Action: 7 normalized floats clipped to [-1,1], robosuite BASIC/right OSC_POSE, base-frame delta xyz (+/-0.05 m per command), axis-angle delta rotation (+/-0.5 rad), gripper velocity command (-1 open, +1 close). Fixed impedance kp=150 and damping ratio=1. Reference rotates by zero; rotations remain in the common learned action contract. No hidden action-stage conversion for students. Policy horizon 8, execute 2 actions then replan; simulator action stream 20 Hz, inference wall-clock speed measured separately. Early pilots executed 1 or 2, recorded in their manifests.

Instruction encoding for compact policies: explicit one-hot red/green object and blue/yellow receptacle tokens (4 values). This is constrained semantic conditioning, not a pretrained language model. Do not claim paraphrase generalization without additional tests. SmolVLA uses the actual instruction text and official tokenizer.

Teacher alone observes cube truth positions, goal positions, curriculum phase and current waypoint error. Script initializes BC, then PPO uses actual environment rollouts and rewards. High-level curriculum phases are privileged teacher state; they must never enter student batches. Script, BC and PPO checkpoints/trajectories have distinct provenance. At PPO resume, optimizer/RNG persist, but simulation restarts an episode; bit-exact interrupted physics replay is not claimed.

Success requires the selected object's center within 4.3 cm of the selected tray's center in xy, center z in (0.816, 0.855) m, no detected gripper grasp, and an earlier lift above 0.89 m. This is a center-proximity criterion; it does not verify full object containment or sustained settling. Wrong target, wrong destination, table fall and placement error are recorded separately. This is adapted simulation evaluation, not a LIBERO score.

The success check is instantaneous. Wrong target means the non-selected cube was lifted above 0.89 m at any point or was within 4.3 cm xy of either tray at the recorded endpoint. Wrong destination means the selected cube met the released center-proximity criterion at the other tray, at any recorded step. Collision means robot/gripper contact with table, goal wall or gray distractor penetrating more than 1 mm; object grasp contact is excluded. Drop means either cube center fell below 0.75 m at any point. Metrics can overlap. Placement errors are terminal selected-object offsets to the selected tray center, including failed episodes.

HDF5 per episode with gzip/shuffle lossless RGB uint8, depth float32, camera calibrations/points/masks, timestamp, state/action/tokens. Attributes include instruction, scene seed/config, split, success/failures, teacher checkpoint hash and provenance. Metadata truth IDs are never model inputs. Seeds [0,100000) train, [100000,200000) validation, >=200000 test; entire episodes and scene configurations split, no adjacent-frame leakage. Failures stored and excluded only from success demonstration training, available for diagnosis. Test seeds excluded from teacher learning and collection for training.
